## 重要決策與理由

### 一張試算表、一個伺服器一個分頁

原本設計成「每個伺服器管理員各自接自己的試算表」，實際使用方式是
「我自己維護一張表，每進一個新群組就開一個分頁」。因此：

- 試算表 ID 固定在 `PROMPT_SPREADSHEET_ID`
- `/設定資料庫` 只需指定分頁名稱
- 設定權限從「伺服器管理員」收緊到「機器人擁有者」

**收緊權限同時解決了一個資訊外洩問題**：共用同一張試算表時，
「找不到分頁」的錯誤訊息會列出所有分頁名稱，等於讓任何群組的管理員
看到其他群組的分頁名。改成擁有者限定後，能看到列表的只剩自己。

擁有者是向 Discord 的 `/oauth2/applications/@me` 即時查詢，不是寫死 ID，
轉移 App 擁有權不用改程式。

### 資料結構：三欄

| 人設名稱 | 中文提示詞 | 英文提示詞 |
|---|---|---|

規則：名稱必填且不可重複，中英文至少填一項。

**欄位照標題名稱對應，不照位置。** 讀和寫都是。已實測把標題列改成
「英文／名稱／中文」後，新增與更新仍寫到正確的欄。

### `/修改人設` 留空 = 保持原值

留空若解讀成「清空」，只想改中文的人會不小心把英文抹掉。
要清空得明確操作。

實作上用 `values:batchUpdate` **只寫指定的那幾格**，不整列覆蓋 ——
整列寫入會把使用者之後自己在 D、E 欄加的東西清掉。

### 寫入一律用 `valueInputOption=RAW`

內容來自使用者輸入。Google 預設的 `USER_ENTERED` 會把
`=IMPORTRANGE(...)` 之類的字串變成真的公式在試算表裡執行，
等於讓任何能下指令的人在擁有者的試算表裡跑程式碼撈其他分頁的資料。

已實測：送入該字串後讀回仍是純文字，未被求值。

### 寫入前略過快取

判斷名稱是否重複、定位要改哪一列，用五分鐘前的快取會誤判
（例如剛新增的名稱查不到，導致重複寫入）。所以 `loadForWrite` 直接讀試算表。

反過來，**自動完成一律用快取且可接受過期** —— 它沒有 defer 可用，
Discord 要求 3 秒內回應，而且每打一個字就觸發一次，不能為了新鮮度去等 Google。
自動完成失敗時回空清單而不是錯誤：壞掉的建議清單會讓輸入框卡死，比沒有建議更糟。

### `/設定資料庫` 的「自動建立」預設開啟

進新群組時本來就還沒有分頁，這是常態。預設關閉等於每次都要多點一次。
誤建的風險用回覆區分：建立時標題是「已建立新分頁」而非「設定完成」。

### 切換分頁會明確警告

原本重跑 `/設定資料庫` 指到別的分頁會靜默覆蓋，舊分頁的資料還在試算表裡
卻再也讀不到 —— 實際上已經產生一個孤兒分頁，實測時就踩到過一次。
現在切換時會用橘色明講「原本 X → 現在 Y」以及舊分頁從此讀不到。

### 指令紀錄

開放寫入給所有成員後，需要能事後查出誰改了什麼。

- 修改類記「改前 → 改後」，只記「執行了修改」事後看不出變動了什麼
- 被擋下的操作（名稱重複）也記，看得出有人嘗試過及原因
- `guild_name` / `user_name` 存寫入當下的快照，日後改名不影響既有紀錄
- **寫紀錄失敗一律吞掉**：少一筆稽核紀錄可以接受，讓指令本身失敗不行
- 保留 30 天，由 Cron Trigger 每天 18:00 UTC（台灣凌晨 2 點）清理

### 移除身分組功能

`/身分組面板` 從頭到尾沒實測過，而且它是機器人唯一需要 Discord 權限的功能。
拿掉之後邀請連結可以用 `permissions=0`，對方看到的授權畫面完全乾淨 ——
斜線指令的回應本來就不需要權限，讀寫試算表也跟 Discord 權限無關。

元件分派機制保留著（目前空的），賭圖玩法的作答按鈕會用到。

### 修改與刪除都限建立者本人

刪除不可逆，所以一開始就設成嚴格本人限定，管理員也不能代刪。
後來發現修改完全沒有檢查 —— 別人刪不掉你的資料，卻可以把內容整個覆蓋掉，
實質效果相近。兩者改用同一套規則。

歸屬記錄在試算表的「建立者」欄，存 Discord 使用者 ID 而不是顯示名稱 ——
名稱會被改，ID 不會。沒有建立者的舊資料任何人都不能用指令動它，
只能直接編輯試算表。

刪除採按鈕二次確認，而且**按下按鈕的當下會重新讀取並再驗證一次**：
從下指令到按確認之間，資料可能已被改動、列號也可能因為別人刪除而位移。
確認 token 存在 D1 而非 `custom_id`（後者有 100 字元上限，人設名稱本身就可能到 100 字元），
一次性取用，重複點擊不會重複刪除。

### 手機版的複製按鈕

原本提示詞放在 embed 的程式碼區塊裡，手機上點不了複製。
兩層原因：embed 裡的內容沒有複製功能，而且**能點一下複製的是行內程式碼，不是程式碼區塊**。
改成訊息本文 + 行內程式碼才解決。

行內程式碼不能跨行，所以換行收成空格；內容含反引號時自動加長分隔符，
否則程式碼區段會在反引號處提前截斷。

### 開放公開加入

決定讓所有伺服器共用同一張試算表（各自一個分頁），而不是各接各的。
代價是別人的資料會存在自己的 Google 帳號下、也佔自己的額度。

開放設定權限之後補了三道防護，否則任何伺服器的管理員都能讀別人的資料：

- **分頁本身綁定伺服器 ID**（Google 隱藏元資料，不佔儲存格、UI 看不到）。
  比 D1 的登記可靠 —— D1 存的是分頁「名稱」，而名稱可以被改。
- 分頁被其他伺服器登記過就拒絕指過去
- **非擁有者只能建立新分頁，不能接上任何既有分頁** ——
  少了這條，可以靠反覆嘗試名稱探測出別人的分頁並讀取內容
- 分頁清單只對機器人擁有者顯示

指令同時改為全域註冊，新加入的伺服器才有指令可用。

### 訊息語氣

約 70 處使用者可見文字改寫得輕鬆一些，但**刪除確認的「無法復原」警告與
Google 權限錯誤的指引一字未改** —— 那兩種訊息可愛化會讓人低估後果、
或讀不出該怎麼修。

## 環境備忘

延續前一天那幾個 Windows 坑，今天新增：

- **`process.exit()` 在 Windows 上會觸發 libuv assertion**，把成功的執行報成離開碼 9。
  改用 `process.exitCode`。
- **PowerShell 的反引號是跳脫字元**，用 `node -e "..."` 傳含反引號的字串會被吃掉。
  改用編輯工具或 heredoc。
- **測試不要寫死試算表內容**。曾因為斷言「內容等於某字串」而在使用者編輯試算表後
  誤報失敗 —— 程式其實是對的。
- **排程可以本機測**：`wrangler dev --test-scheduled` 之後打
  `http://localhost:8787/__scheduled?cron=...`。
- **PowerShell 的 `Get-Content` 會弄壞 UTF-8 中文**，讀檔請用編輯工具而不是它。
- **ESM 循環相依會依載入順序決定生死**。`/help` 原本反向 import 指令註冊表，
  真實 Worker 的載入順序剛好避開，但單獨載入 `help.js` 就會在暫時性死區爆掉。
  改由註冊表主動注入。這種「能不能跑取決於誰先被載入」的設計遲早會在重構時炸。
- **Workers 對執行期動態 `import()` 支援有限**，能靜態匯入就不要用它。
